Treasury 0.1.4 filters and sorts a table's rows on the server, shows the selected row beside
the grid, and keeps the navigator up to date after you create or drop a table. It also fixes two
settings that were not saved, one of them the switch that turns the update check off.

## Added

- A filter box above a table's rows. Type a condition, such as `total > 100 and status = 'paid'`,
  and press Enter: Treasury reads only the rows that match, from the server. For a MongoDB
  collection, type a query document such as `{"status": "open"}`. The condition must be one
  expression, so it cannot end the statement or add clauses of its own; anything else is
  refused with the reason, and the rows stay as they were. Clear reads every row again.
- Sorting by column. Click a column header on a table's Data page to sort by that column,
  smallest first; click again for largest first, and a third time to stop sorting by it.
  Shift-click adds a column to the sort. The server sorts, so the order covers every row, not
  only those read so far.
- The row panel. Row panel, in the bar under the grid, or F7, shows the selected row beside the
  grid, one field per line with its type, including changes not saved yet. It stays open until
  you close it, also after a restart.
- The navigator reads a connection's objects again once a statement that creates, changes or
  drops one has run, and keeps open the folders you had open.

## Fixed

- Turning off "Check for a new version" in Settings was not saved, so Treasury went on asking
  GitHub for a new version at start and every 6 hours. It is saved now, and stays off.
- The width of the sidebar was not saved either, so it went back to its default at the next
  start.
- Refresh in the navigator's toolbar did not read the objects again.
- Reading a table's rows again (Refresh, a filter or a sort) while the grid holds changes not
  saved yet is refused, with a message, instead of dropping the changes.
- A tip still said to double-click a connection to edit it; that moved to the right-click menu
  in 0.1.3.

## Updating from 0.1.3

Treasury offers the update in the bar at the bottom of its window when it starts, or at once
from Settings, Check now. Choose Install and restart. Or run the new installer over the old
version; there is no need to uninstall, and your connections and passwords stay.

If you turned off the update check in 0.1.3, it did not stay off, as described above. Turn it
off again in 0.1.4 and it will.

## Downloads

| Platform | Files |
|---|---|
| Linux x64 | `.AppImage`, `.deb`, `.rpm` |
| Linux arm64 | `.AppImage`, `.deb`, `.rpm` |
| macOS, Apple silicon and Intel | `.dmg` |
| Windows x64 | `-setup.exe` installer, `.msi` |

Before the first launch:

- macOS: the app is not notarized by Apple yet, so macOS stops it the first time. Open it once,
  then choose Open Anyway in System Settings, Privacy & Security.
- Windows: the installers are not code-signed yet, so SmartScreen may warn you. Choose More info,
  then Run anyway.
- Linux: install the `.deb` or `.rpm` with your package manager, or make the AppImage executable
  and run it. Passwords go to the Secret Service (GNOME Keyring or KWallet).

## Checking a download

`SHA256SUMS` lists the checksum of every file; check yours with
`sha256sum -c SHA256SUMS --ignore-missing`. Every file also has a build provenance attestation,
which `gh attestation verify <file> --repo sepehrmohseni/treasury` checks, and the CycloneDX SBOM
lists every dependency.
